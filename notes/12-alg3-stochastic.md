# Алгоритм 3 — Стохастическая модель утечки (4.3.2.2)

## Идея

Алгоритмы 1 и 2 **предполагали** модель: `wt(v)`, где каждый бит вносит ровно
единицу. Это неправда — разные линии шины имеют разную ёмкость и текут по-разному.

Стохастическая модель не предполагает, а **подбирает** вклад каждого бита:

    L(v) = a₀·v₀ + a₁·v₁ + ... + a₇·v₇ + шум          (ур. 4.24)

где `vₛ` — отдельные биты значения `v`, а `aₛ` находятся методом наименьших
квадратов по профилирующим трассам.

**Вес Хэмминга — частный случай, где все `aₛ` равны.** То есть это обобщение
алгоритма 2, а не замена.

## Три шага книги

| Шаг | Что делаем |
|---|---|
| SLM a | собрать утечки в POI со всех профилирующих трасс → вектор `ℓ_pf` |
| SLM b | построить матрицу `M_v`: строка на трассу = биты её истинного `v` |
| SLM c | `â = (M_vᵀ M_v)⁻¹ M_vᵀ ℓ_pf` (ур. 4.26) |

Дальше шаг 12 использует `L(v̂)` как предсказанный сигнал, шаг 13 — та же
корреляция в POI, что и в алгоритме 2.

    стохастическая модель:  восстановлено -3  (истина +4)  — не стабилизируется
    вес Хэмминга:           восстановлено +4               — стабильно с 22 трасс

Скрипт: `siphon/alg3_stochastic.py`

Это **не баг реализации**. Это нарушенное условие применимости, и оно
интересное — его стоит вынести в диплом.

## Что пошло не так: матрица вырождена

    rank(M_v) = 4 из 8

Две отдельные причины:

**1. Биты 0 и 1 никогда не меняются.**
Истинный вес `w = 4`, значит `v = 4·x` — всегда кратно четырём. Младшие два бита
тождественно нулевые. Столбцы нулевые → в базис не вносят ничего.

**2. Биты 5, 6, 7 всегда совпадают между собой.**
Достижимые `v` лежат в диапазоне [−28, 28]. В 8-битном дополнительном коде:

    +28 = 0b00011100   → биты 5,6,7 = 0,0,0
     −4 = 0b11111100   → биты 5,6,7 = 1,1,1

То есть все три старших бита кодируют **просто знак** и коллинеарны.

Итого: 8 битов − 2 мёртвых − 2 избыточных = **ранг 4**.
Матрица `M_vᵀ M_v` **необратима**, формула 4.26 из книги неприменима буквально.
Пришлось решать через `lstsq` (псевдообратная, минимальная норма).

## Настоящая причина: нарушено условие книги

Книга прямо пишет в SLM Step b:

> «Since the stochastic leakage essentially assumes each value of `v` has a
> different leakage, **we require that all possible values of `v` appear in
> `M_v`**… we should take enough random plaintexts so that all values of `v` appear.»

У нас это **невыполнимо по построению**:

| Гипотеза | Сколько её значений `v` встречалось при профилировании |
|---|---|
| w = ±4 (истина) | **14 из 14** |
| w = ±2, ±6 | 4–6 из 14 |
| w = ±1, ±3, ±5, ±7 | **2 из 14** |

Для `w = +7` модель предсказывает утечку значений `v` до ±49, которых при
профилировании **не было ни разу**. Она экстраполирует в битовые комбинации,
которых никогда не видела. Отсюда и мусорный ответ −3.

### Почему в шифре такой проблемы нет
`v = SBox(k ⊕ p)`. При фиксированном `k`, когда `p` пробегает все 16 значений,
`v` тоже пробегает **все 16** — XOR биективен. Профилирование автоматически
покрывает всё пространство, и модель годится для любой гипотезы ключа.

У нас `v = w·x` при **фиксированном** `w`: достижимы только кратные `w`.
Полное покрытие недостижимо в принципе.

## Как это чинится

Ответ тоже в книге, **P-DPA Step 2**:

> «We first collect a set of traces for profiling using the clone device with
> random plaintexts **and random keys**.»

**Случайные ключи.** То есть профилировать надо не при одном весе, а при
**разных весах**. Тогда `v = w·x` покроет весь диапазон, `M_v` станет полного
ранга, и модель будет годиться для любой гипотезы.

Мы этого не сделали: сняли профилирующие трассы одной прошивкой с `w = 4`,
потому что вес зашит в прошивку. Для исправления нужно **перепрошивать плату
под каждый вес** и собирать профилирующий набор по нескольким весам.

### Практическое препятствие
Для прошивки из `siphon/` у нас есть только `.hex`
и `network_config.h` — **исходников сборки нет**. Чтобы менять вес, нужен
исходник из репозитория `ymarochok/Binary_Codes_Against_SCA_BW`.

Для собственного проекта `cpa_mnist/` исходники **есть**
(`firmware/mnist_nn/`: `nn.c`, `main.c`, `weights.h`, `makefile`),
и `nncpa flash` умеет собирать и заливать. Там это делается без препятствий.

## Что это даёт диплому

Самостоятельный результат: **алгоритм из учебника имеет условие применимости,
которое в нейросетевой постановке структурно невыполнимо** при фиксированном
весе. Причина — линейность `v = w·x` против биективности `SBox(k ⊕ p)`.
Указан и способ исправления, и он согласуется с текстом книги (случайные ключи).

## ⚠ То же самое ждёт алгоритм 4
Шаблоны строятся по значениям `v`. Если гипотеза требует шаблон для значения,
которого при профилировании не было, шаблона просто **не существует**.
Это та же самая проблема, обсудить перед реализацией.

# Попытка починить без перепрошивки (алгоритм 3b) — не вышло

Скрипт: `siphon/alg3b_multipoi.py`

## Идея
Раз `input[1]` читают все шесть нейронов, в тех же трассах есть несколько
разных весов, каждый в своей точке (см. `05-poi-ambiguity.md`):

    POI 4237 -> w = +4    v = 4x    (кратные 4)
    POI 3746 -> w = −7    v = −7x   (нечётные! оживляют младшие биты)
    POI 4857 -> w = −4    v = −4x

Собрали пары «(значение, утечка)» со всех трёх точек, утечку в каждой точке
стандартизовали (у разных отсчётов свои смещение и масштаб), и подобрали `α`
по объединённому набору.

## Что улучшилось
- ранг вырос **с 4 до 7** из 8 — нечётные значения `−7x` оживили биты 0 и 1
- различных предсказанных значений стало **14 вместо 3**
- разброс коэффициентов 1.35 — то есть допущение HW о равном вкладе битов
  **действительно неверно**

## Но атака всё равно провалилась
    стохастическая (мульти-POI): восстановлено +3, запас 0.0222
    вес Хэмминга:                восстановлено +4, запас 0.0008

Стохастическая модель ошибается **увереннее**, чем HW угадывает.

## Почему: две причины, вторая решающая

**1. Модели в разных точках не совпадают.** Подобрали `α` в каждой точке
отдельно и сравнили:

    corr(a[4237], a[4857]) = +0.909    (оба веса кратны 4 — форма набора та же)
    corr(a[4237], a[3746]) = −0.523    отрицательная
    corr(a[3746], a[4857]) = −0.587

Если бы утечка была одной и той же функцией битов во всех точках, корреляции
были бы близки к +1. Значит допущение пулинга нарушено.

**2. При одном фиксированном весе `α` вообще не идентифицируема.**
В точках 4237 и 4857 ранг равен **4 из 8**: коэффициенты определены лишь
с точностью до четырёхмерного нуль-пространства. `lstsq` возвращает
представителя минимальной нормы — по сути произвольного. Это видно прямо
в цифрах:

    a0 = a1 = 0           (мёртвые биты)
    a5 = a6 = a7          (коллинеарные столбцы)

Это артефакт вырождения, а не измеренная физика. Поэтому сравнение
`a[4237]` с `a[3746]` мало что значит: первое — не оценка, а заглушка.

## Единственный корректный путь

Менять вес **при неизменной точке измерения**. То есть:

1. перепрошить `L1_W[0][1] = w` для `w = 1…7`
2. каждый раз снимать трассы
3. брать утечку в **одной и той же** точке — умножение нулевого нейрона
4. подобрать `α` по объединённому набору

Тогда все пары «(значение, утечка)» относятся к **одной инструкции**,
а `v = w·x` покрывает широкий диапазон. Ровно это и предписывает книга
в P-DPA Step 2: «profiling … with random plaintexts **and random keys**».

Важно: все захваты должны быть **одной сборкой прошивки**, иначе поедет POI.
Значит атакующий набор тоже надо переснять этой же сборкой.
