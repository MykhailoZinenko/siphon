# Контекст: что мы атакуем

## Устройство и сеть
- Плата **CWLITEARM** (ChipWhisperer), прошивка `firmware-CWLITEARM.hex`
- Сеть: **10 входов → 6 нейронов → 1 выход**, квантованная в `int8`
- Веса лежат в `network_config.h`, диапазон **−7…7**
- Умножение `int8 × int8`, накопление в `int32`, затем переквантование (`M0`, `N`)

## Цель атаки
Восстановить **один вес**: `L1_W[0][1] = 4`
(нулевой нейрон первого слоя, первый вход).

## Данные (`siphon/traces/`)
- 5000 трасс, по **24 430** отсчётов каждая
- `inputs.txt` — матрица (5000, 10)
- **Ненулевой только столбец 1**, остальные входы = 0

Это и есть приём «hotspot»: обнуляя все входы кроме одного,
мы изолируем умножение ровно на нужный вес — иначе в утечке
смешались бы все 10 произведений.

## Соответствие «шифр → нейросеть»

| Учебник (PRESENT) | Наш случай |
|---|---|
| Байт/ниббл ключа `k`, 16 гипотез | Вес `w`, **14 гипотез** (−7…7 без нуля) |
| Открытый текст `p` | Входное значение `x` (столбец 1) |
| Промежуточное значение `v = SBox(k ⊕ p)` | `v = w · x` |
| Пик у правильного ключа | Пик у правильного веса |
| Клон-устройство с известным ключом | Наша же прошивка с известным весом |

**Главное отличие:** в шифре `v` считается через **нелинейный** S-box,
у нас — через **линейное** умножение. Из этого следуют все проблемы адаптации.
